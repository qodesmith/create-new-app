# Conventions

Rules that apply to all skills in this project.

## Finalize

- Run `biome check --write <files>` on all created/edited files

## Comments

- Single-line comments use `//` syntax
- Multi-line comments use JSDoc syntax (`/** ... */`, each line prefixed with ` * `)
- Never let a comment line exceed 80 characters — wrap onto the next line

## NEVER

- Add app-wide context providers in `__root.tsx` — they go in `src/client/app.tsx` wrapping `<RouterProvider>` (alongside `QueryClientProvider` / `JotaiProvider`). `__root.tsx` is for per-page UI, not providers.
- Use raw `fetch` on client — always Hono RPC via atoms (`apiClientAtom` / `apiAuthClientAtom`)
- Use raw Radix — always Shadcn components
- Import the full `motion` from `motion/react` in components — always use `m` (`<m.div>`, etc.). The root `<LazyMotion features={domAnimation} strict>` in `app.tsx` supplies animation features; `strict` makes a `motion` import throw. Use `domMax` instead of `domAnimation` only if drag/pan/layout-projection is needed.
- Use the bare `<Label />` primitive or a raw `<label>` inside a form — always wrap inputs with `<Field>` + `<FieldLabel>` from `@/client/components/ui/field`. `<Label />` is for one-off labels outside forms only.
- Use Drizzle async APIs — always use sync terminators (`.all()`, `.get()`, `.run()`, `.values()`)
- Touch `routeTree.gen.ts` — auto-generated by TanStack Router
- Touch `authSchema.ts` — managed by Better Auth
- Touch `src/server/db/drizzle/` — auto-generated migrations
- Modify build/dev scripts, Dockerfiles, fly.toml, .env, tsconfig, biome config without permission
